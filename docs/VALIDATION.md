# Проверка на комплекте куратора

Комплект включает учебный отчёт о НИР, пустой шаблон на 23 требования,
заполненный эталон и рекомендации. Приложение получает отчёт и пустой шаблон.
Эталон используется отдельно для сверки после запуска.

## Воспроизведение

```bash
mkdir -p output
uv run sirius-proj check 'examples/Отчет о НИР учебный.docx' 'examples/Чек-лист.docx' \
  -o output/curator-full-checked.docx --json output/curator-full-checked.json
uv run sirius-proj check 'examples/Отчет о НИР учебный.docx' 'examples/Чек-лист.docx' --rag \
  -o output/curator-rag-checked.docx --json output/curator-rag-checked.json
```

В окне выберите эти же два файла. Для второго прогона включите RAG в настройках.
Сохраните заполненную копию в Word или экспортируйте результаты в Excel. В итоговой
таблице сверьте статусы, смысл пояснений и подлинность цитат с эталоном.

Команды используют локальные файлы куратора. В Git хранятся исходники приложения
и отдельный публичный учебный пример. Результаты в `output/` также остаются локальными.

## Что проверяется

- Пункты 1–5 обрабатываются кодом по размерам страниц, заголовкам и подписям объектов.
- Пункты 6–23 проверяет Qwen2.5 7B по тексту и таблицам с учётом комментария из шаблона.
- В обоих режимах модель выбирает адреса источников. В отчёт попадает исходный текст
  соответствующих абзацев и ячеек. Совпадение цитаты подтверждает её происхождение.
- Сравнение статусов показывает расхождения с эталоном. Смысл пояснений и достаточность
  выбранных доказательств оцениваются отдельно.

Регрессионные проверки кода выполняются командами `uv run pytest -q` и
`uv run ruff check src tests`.

показывает требуемую редакцию и замечание, но не саму ячейку с фактическим номером.
