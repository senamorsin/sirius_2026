## Пробный запуск

Воспроизводимый код: `scripts/evaluate_nli.py`. Веса загружаются строго локально,
инференс выполняется с eval()/inference_mode(), адаптер не применяется.
Использовано уже установленное окружение прежнего проекта: PyTorch 2.10.0+cu128,
Transformers 5.23.0, safetensors 0.8.0. Дополнительные зависимости не нужны основному приложению.

```bash
/home/senamorsin/Desktop/lab_proj/.venv/bin/python scripts/evaluate_nli.py
```

Пять диагностических пар дали четыре правильные метки. Полные вероятности и токены,
отсутствующие в словаре, сохранены в `docs/validation/nli-experiment.json`.
Модель различает совпадение 220 В, противоречие 18/25 м и отсутствие сопротивления изоляции.
Но пара «IP54» — «должен быть IP65» ошибочно получила entailment с вероятностью около 0,759.
Для декларативной формулировки «IP65» получена contradiction около 0,775.
В обеих парах токен `65.` отсутствует в сокращённом словаре; также отсутствует `-101`.
Это подтверждённое ограничение словаря, но оно не доказывает единственную причину ошибки:
на классификацию влияет и нормативная формулировка гипотезы.

## Решение для MVP

Компактная модель сохранена для дальнейших экспериментов, но не назначена основным
классификатором технических требований: потеря чисел и обозначений особенно существенна
в этой задаче. Не следует переносить метрики дообученного ансамбля прежнего проекта
на эту базовую модель и технические документы.

Следующий обоснованный эксперимент — полный исходный словарь, неизменённые исходные веса,
отдельный набор нормативных требований и явная проверка чисел/идентификаторов. NLI может
также использоваться для ранжирования найденных оснований через существующий интерфейс Judge.
Для неподтверждённого решения всё равно применяется общая политика проверки цитат.
